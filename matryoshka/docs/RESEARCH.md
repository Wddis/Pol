# Matryoshka: техническое исследование и план разработки

*Дата: 2 ноября 2026. Статус: на утверждение. Основной код по этому плану ещё не писался.*

## 0. Коротко

- **Целевое устройство:** Redmi Note 8 (Snapdragon 665, 4 ГБ ОЗУ, MIUI 12.5 на Android 11), **без root**.
  На таком телефоне нет аппаратной виртуализации (KVM), а без root недоступны контейнеры.
  Единственная архитектура, которая даёт пригодную скорость, — **виртуализация в пространстве
  пользователя** («userspace»). По этому принципу работают VPhoneGaGa/VPhoneOS, VMOS и twoyi: второй
  Android работает как набор процессов обычного приложения на ядре телефона.
- **Готового открытого решения такого типа нет.** twoyi (единственный открытый проект) закрыт
  авторами «из-за сложности», его ROM и загрузчик не открыты. Код VMOS для Android 5.1 опубликован
  под некоммерческой лицензией. Ядро этой архитектуры придётся **писать самим**: userspace-binder,
  виртуализацию путей, UID и устройств.
- **Остальное можно взять готовым:** систему Android 11 (LineageOS 18.1, сборка Waydroid для arm64),
  графику (gfxstream и goldfish-opengl от Google, Apache-2.0), Magisk (официальный механизм «живого»
  запуска без boot-образа, как для эмуляторов), microG, а также наше текущее приложение
  Matryoshka (UI, ADB-клиент, менеджер образов).
- **Размер:** реально около **1,1–1,25 ГБ** на диске и **~0,6 ГБ** на загрузку.
  Это проверено на реальном образе, а не взято из оценок.
- **ОЗУ в простое:** реально **~450–650 МБ** с microG. Цель 300–400 МБ достижима только без сервисов
  Google. С настоящими GApps — 700–950 МБ (подробности в разделе 9).
- **Рекомендация:** движок «Nest» (userspace) как основной для телефонов без root, а уже
  написанные движки «Гипервизор» и «Контейнер» — для телефонов, где они возможны. Гостевая
  система у всех трёх общая.

## 3. VPhoneGaGa / VPhoneOS: анализ и наш аналог root

**Что известно из открытых источников** (приложение закрыто; мы его не декомпилировали и не
будем — это нарушило бы лицензионное соглашение):

- Гость — Android 7 бесплатно, Android 10/12 и 64-битные приложения — по подписке VIP
  ([Android Authority, 08.2026](https://androidauthority.com/play-32-bit-games-new-android-phone-3703230)).
- Root на хосте не нужен. Root гостя включается переключателем (VIP).
- Magisk ставится **без патча boot-образа**. В гостевом терминале выполняется скрипт, основанный
  на `emulator.sh` из Magisk, затем `magisk_root enable` и перезагрузка гостя
  ([reidentify/Magisk-on-VphoneGaga](https://github.com/reidentify/Magisk-on-VphoneGaga),
  [andnixsh](https://www.andnixsh.com/2023/08/how-to-install-magisk-on-vphonegaga-vm.html)).
- Ограничения: работает только MagiskSU. MagiskHide недоступен («ядро слишком старое», нет mount
  namespaces). Модули не ставятся, стадия post-fs-data заблокирована. Нужен старый Magisk Manager v8.

**Как это устроено.** Официальный Magisk поддерживает «живой» запуск без boot-образа для эмуляторов
([`avd_setup.sh`](https://github.com/topjohnwu/Magisk/blob/master/scripts/avd_setup.sh), API 24–36).
Скрипт выполняет такие шаги:

1. Останавливает zygote (`stop`).
2. Монтирует tmpfs в `/debug_ramdisk` (или `/sbin`).
3. Раскладывает `magisk`, `magiskpolicy`, `su` и `resetprop`.
4. Выполняет `magisk --preinit-device`, затем `magiskpolicy --live`.
5. Выполняет `magisk --post-fs-data`, запускает zygote (`start`), затем `magisk --service` и `--boot-complete`.

VPhoneGaGa делает примерно то же, но после загрузки и в урезанной среде. Отсюда и ограничения.

**Наш вариант лучше и честнее:**

| Шаг | VPhoneGaGa | Matryoshka «Nest» |
|---|---|---|
| Где запускается Magisk | скрипт после загрузки | **наш init-хук до zygote**: мы контролируем init гостя, поэтому стадия post-fs-data работает штатно |
| Установка | терминал + скрипт | кнопка «Root (Magisk)» в настройках VM. Приложение скачивает **официальный** APK, раскладывает бинарники в `/data/adb/magisk` и перезапускает гостя |
| Перезапуск | полная перезагрузка VM | «мягкий» перезапуск: перезапускается только userspace гостя, несколько секунд |
| Модули | не работают | работают: `mount --bind` модулей превращается в записи нашей таблицы путей (виртуальные mount namespaces) |
| DenyList / скрытие | нет | возможно: у каждого процесса гостя своя «таблица монтирования» |
| Zygisk | нет данных | должен работать: загружается через native bridge, это обычный userspace |
| Версия Magisk | ≤ v8 | актуальная. Проверяется на каждом релизе Magisk, `avd_setup.sh` — официальный ориентир |

SELinux в гостевой userspace-среде выключен (ядро общее с хостом, политика хоста действует).
Шаг `magiskpolicy --live` поэтому пропускается — Magisk такую ситуацию поддерживает.

**Что внутри образа Waydroid** (скачал и распаковал):
`system_ext/apex/com.android.vndk.v28` и `v29` занимают **210 МБ** и нам не нужны. WebView занимает
**236 МБ** (в двух архитектурах). Есть Camera2, Gallery2, Etar, Eleven, Jelly, Recorder, Seedvault,
телефония и NFC (~180 МБ). CJK-шрифты — 44 МБ. Vendor содержит готовые простые HAL: `hwcomposer.waydroid`,
`gralloc.default`, `audio.primary.waydroid`, sensors, power, vibrator, keymaster 4.0.

**Важно.** Как есть этот образ на нашем движке не запустится: он ждёт настоящего ядерного binder и
LXC. Мы **пересобираем из того же исходного дерева** (LineageOS 18.1 + vendor_waydroid) только
изменённые модули — bionic, libbinder, init, несколько сервисов фреймворка — и свой vendor (HAL).
Остальное остаётся байт-в-байт как у Waydroid.

## 5. Интеграция Magisk

| Движок | Способ | Полнота |
|---|---|---|
| **Nest (userspace)** | Init-хук по образцу `avd_setup.sh` до запуска zygote + виртуальные mount | MagiskSU, модули, Zygisk (ожидаемо); DenyList позже |
| Гипервизор / Эмулятор | Патч boot.img официальным `boot_patch.sh` внутри гостя (**уже реализовано**) | Полный Magisk |
| Контейнер | Тот же init-хук, что у Nest (настоящие mount доступны) | Почти полный |

Лицензия: Magisk распространяется по GPL-3.0. Мы не встраиваем его в APK, а скачиваем официальный
релиз по действию пользователя. Init-хук — наш собственный код, написанный по документированному
порядку шагов. Так Matryoshka остаётся под Apache-2.0.

## 8. Архитектура «Nest»

```
Хост-приложение Matryoshka (targetSdk 28, uid приложения)
 ├─ UI (Compose)                ← уже есть
 ├─ nestd: супервизор гостя (C++/Rust, native)
 │   ├─ vbinder: binder-драйвер в userspace (ioctl-совместимый, поверх unix-сокетов)
 │   │     три контекста: binder / hwbinder / vndbinder; refs, oneway, death notifications, передача fd
 │   ├─ vfs: таблица путей rootfs + виртуальные mount namespaces (для Magisk и модулей)
 │   ├─ vdev: /dev/{input,binder,ashmem→memfd,...}, /proc и /sys в нужном объёме
 │   ├─ vprops: property service гостя
 │   └─ launcher: запуск процессов гостя через linker64 гостя
 ├─ рендер: gfxstream-хост → EGL/GLES (Adreno) → SurfaceView
 └─ аудио: AAudio, ввод: прямые input_event
Гость: Android 11 (LineageOS 18.1, урезанный), процессы — дети nestd
 ├─ bionic с перехватом путей, UID и системных вызовов (+ seccomp-SIGSYS для «сырых» вызовов)
 ├─ libbinder → /dev/binder перенаправлен в vbinder
 ├─ init → servicemanager/hwservicemanager → zygote(64/32) → system_server
 ├─ HAL: hwcomposer/gralloc (буферы в рендер хоста), audio (сокет), sensors, power (заглушки)
 ├─ сеть: сокеты хоста напрямую; «виртуальная Ethernet-сеть» для ConnectivityService; netd-lite
 ├─ хранилище: /sdcard без FUSE (через таблицу путей)
 └─ Magisk init-хук, microG
```

**Почему перехват в bionic, а не ptrace (PRoot):** гостевой bionic мы собираем сами, поэтому
перехват путей и UID стоит почти ничего. ptrace требует переключения контекста на каждый системный
вызов. Резервный вариант для статических бинарников и «сырых» `svc` — seccomp с возвратом SIGSYS.

**Почему targetSdk 28:** с targetSdk 29 Android запрещает запуск бинарников из данных приложения
(W^X, [Termux](https://github.com/termux/termux-packages/wiki/Termux-and-Android-10)). Termux и twoyi
используют тот же приём. Минус: такой APK нельзя опубликовать в Google Play, распространение
возможно через GitHub или F-Droid.

| − лишние приложения (камера, галерея, календарь, музыка, браузер, телефония, NFC, Seedvault…) | −180 |
| − CJK-шрифты и словари клавиатуры (докачка по желанию) | −80 |
| + наши модули (bionic, libbinder, HAL) | +15 |
| vendor | +85 |
| **Итого базовая система** | **≈ 1 290 → после дедупликации около 1,1–1,25 ГБ** |
| + microG | +45 |
| + GApps пользователя (pico) | +200…300 |
| Загрузка (сжатый образ, коэффициент ~0,45 как у Waydroid) | **≈ 550–650 МБ** |
| Вариант «только 64 бит» (без 32-битных игр) | ещё −150 |

Цель 0,9–1,5 ГБ **достижима**: базовая система 1,1–1,25 ГБ, с GApps около 1,5 ГБ.
`/data` гостя растёт отдельно, по мере установки приложений.

**ОЗУ в простое** (оценка по типичным значениям PSS Android 11 с настройками low_ram/Go; точно
измерим на этапе 3):

| Процессы | МБ |
|---|---|
| init, servicemanager, HAL, logd и др. | 30–40 |
| zygote64 (zygote32 запускается только по требованию) | 40–60 |
| system_server | 110–150 |
| SurfaceFlinger + рендер на стороне хоста | 50–90 |
| SystemUI + лаунчер (облегчённые) | 90–130 |
| прочее (media, keystore, netd-lite) | 30–50 |
| **Без GMS** | **≈ 350–520** |
| + microG | +60–100 → **≈ 450–620** |
| + настоящие GApps | +250–400 → **≈ 700–950** |

**Почему не 300–400 МБ с GMS.** Один только system_server Android 11 занимает 100+ МБ, а Google Play
Services — от 250 МБ. Ближайший реалистичный вариант: **~450 МБ с microG** при агрессивных
настройках. Для этого нужны `ro.config.low_ram=true`, ленивый zygote32, ограничение кэша процессов,
zram на хосте и отложенный запуск microG.

**Важно для 4 ГБ телефона:** MIUI сама занимает около 2,5 ГБ. С microG и одним открытым
приложением гостю хватит памяти, а YouTube и игра одновременно с GApps будут на грани, и хостовый
LMK может выгружать гостя.

## 10. Библиотеки, инструменты, технологии

- **Хост-приложение:** Kotlin, Jetpack Compose (уже есть); NDK r27 (C++20) или Rust (cargo-ndk) для `nestd`;
  gfxstream-хост + EGL; AAudio; JNI.
- **Гость:** исходники LineageOS 18.1 + vendor_waydroid; наши патчи bionic, libbinder, init,
  frameworks/base (ConnectivityService, StorageManager) и HAL.
- **Сборка:** Linux-машина с ~300 ГБ диска и 32+ ГБ ОЗУ для синхронизации LineageOS и сборки
  отдельных модулей; GitHub Actions для APK.
- **Компоненты по запросу пользователя:** Magisk (GPL-3.0), microG (Apache-2.0), GApps от пользователя.
- **Тестирование:** юнит-тесты движка на Linux (x86_64-сборка тех же компонентов), затем телефон пользователя.

## 11. Ограничения и решения

| Риск | Решение |
|---|---|
| Нет готового userspace-binder | Пишем свой (`vbinder`) по семантике драйвера Linux; RPC Binder (Android 12) — образец. **Главный риск проекта** |
| W^X при targetSdk ≥ 29 | targetSdk 28 (как Termux), распространение вне Google Play |
| Android 12+: [phantom process killer](https://github.com/agnostic-apollo/Android-Docs/blob/master/en/docs/apps/processes/phantom-cached-and-empty-processes.md) (32 дочерних процесса) | На вашем Android 11 не мешает. На 12+ — переключатель в настройках разработчика или команда через ADB/Shizuku (так же у Virtual Master) |
| seccomp хоста убивает запрещённые вызовы (mount и др.) | bionic гостя не делает их напрямую, а эмулирует. «Сырые» вызовы из игр с античитом — редкий случай, приложение упадёт |
| Нет `/dev/fuse` для приложений | `/sdcard` гостя через таблицу путей, без FUSE |
| Сеть: netd требует прав root в ядре | netd-lite + виртуальная сеть для ConnectivityService; сокеты хоста работают напрямую |
| GPU: драйверы Adreno хоста недоступны гостю напрямую | gfxstream: GLES-команды гостя исполняются в процессе хоста (так делают twoyi и VMOS). Vulkan — позже |
| Play Integrity | Не решается ни в одной ВМ, честно указываем в приложении |
| Нет машины для сборки | См. «Что нужно от вас» |
| Тестирование возможно только на реальном телефоне | Встроенный экспорт логов; вы присылаете их после каждой тестовой сборки |

## 12. Пошаговый план

У каждого этапа есть проверяемый результат («ворота»). Следующий этап начинается только после
прохождения ворот на вашем телефоне.

| № | Этап | Ворота (проверка) |
|---|---|---|
| 0 | Подготовка: репозиторий nestd, CI, тестовый APK «Проверка возможностей» (exec, seccomp, memfd, GLES) | APK на Redmi Note 8 выдаёт отчёт со всеми пунктами ✅ |
| 1 | Launcher + vfs: запуск гостевого `toybox` и `sh` из rootfs с виртуальными путями и UID | В приложении работает shell гостя: `ls /system`, `id` = 0 |
| 2 | **vbinder**: binder-драйвер в userspace; servicemanager + тестовый сервис | `service list` в госте; нагрузочный тест транзакций |
| 3 | Загрузка гостя без экрана: init → zygote → system_server | `sys.boot_completed=1`; **замер ОЗУ в простое** |
| 4 | Графика: gfxstream-хост + hwcomposer/gralloc гостя | Видна домашняя страница гостя, 60 к/с |
| 5 | Ввод, звук, сеть, хранилище | Работают касания, клавиатура, звук, интернет; браузер открывает YouTube |
| 6 | Приложения: установка, импорт и экспорт APK, обмен файлами (переиспользуем текущий код) | Ставится и запускается APK с телефона |
| 7 | microG + импорт GApps пользователя | Вход в аккаунт Google, YouTube с входом в аккаунт |
| 8 | Magisk: init-хук, кнопка root, мягкий перезапуск, виртуальные mount для модулей | Magisk показывает «Установлено», `su` работает, модуль применяется |
| 9 | Оптимизация размера и ОЗУ, ленивые zygote32 и microG | Образ ≤ 1,25 ГБ, ОЗУ в простое ≤ 500 МБ с microG |
| 10 | Игры и производительность, Vulkan по возможности | Набор из 5 популярных игр запускается |
| 11 | Полировка UI, режим нескольких VM, релиз | Релиз на GitHub |

Уже написанное (UI, ADB-клиент, менеджер образов, провижининг Magisk и microG, движки
«Гипервизор» и «Контейнер») переиспользуется на этапах 6–8 и 11.

**Самые трудоёмкие этапы — 2, 3 и 4.** Именно на них «сломались» авторы twoyi. Обещать сроки до
прохождения ворот этапа 3 было бы нечестно. После этапа 3 станет ясно, насколько быстро пойдёт
остальное.

## 13. Что нужно от вас для старта

1. **Утвердить** архитектуру «Nest» и targetSdk 28 (без публикации в Google Play).

   (около $1–3 в час на время сборки). Без неё этапы 2–4 упрутся в невозможность собрать гостевой bionic и libbinder.

   Подтвердите версию MIUI и Android (Настройки → О телефоне).
4. **Название:** «Matryoshka», движок — «Nest», либо ваш вариант.
