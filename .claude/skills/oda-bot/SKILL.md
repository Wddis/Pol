# Бот ODA VPN, сервер ключей и ключ в приложении

Отвечать пользователю по-русски. Сначала прочитать `bot/README.md`: «Состояние» (где работает, адреса, открытый
ключ лицензий, секреты, как обновить), «Меню администратора», «Цель и связь с приложением ODA», «Защита от
обхода», «Решения, принятые с владельцем», риски. Не следить за журналом бота (`wrangler tail`) без просьбы
владельца — это тратит токены.

## Суть за минуту
- Ключ = доступ к **приложению** ODA на срок (подключение ODA делает сама). Срок — с первого ввода ключа в ODA,
  устройства — места на ключе, продление — тем же ключом. Сроки в секундах: тарифы и ключи администратора любой
  длины (минуты … бессрочно = 100 лет).
- Бот и сервер ключей — один воркер Cloudflare (`bot/worker/`, TypeScript без библиотек, D1, webhook `/tg` с
  секретом), работает круглосуточно на `https://oda-vpn-bot.dimazoltinsky.workers.dev`. Версии на Python больше нет.
- Администратор — по Telegram ID в `ADMIN_IDS` (`wrangler.toml`): `/admin` — ключи любого срока, удаление,
  устройства, «Сейчас в VPN», блокировки с причиной (ключ + устройства + владелец), ответы на обращения.
- Приложение: `KeyManager` (сервер, состояние, отпечаток телефона), `License` + `Ed25519` (подпись на телефоне,
  защита от перевода часов, 7 дней без связи), `KeyActivity` (экран ключа / закончился / заблокирован / проверка),
  `KeyWatch` (в VPN-сервисе: сигналы раз в 15 минут, отключение по блокировке), `OdaSheet` (меню, ключ, справка).
  Без ключа `MainActivity` сразу открывает `KeyActivity`; `VpnTunnelService.keyAllows()` не даёт подключиться.
- Открытый ключ лицензий `OSkRbr2ENcvsYqTI8JiusLO3M6k9vXL5m9lHKu8kcB4` вшит в `License.PUBLIC_KEY`; закрытый —
  только в секретах Cloudflare. Поменять его = выпустить новую ODA.
- Дизайн приложения (0.11) — по макету владельца: карточки `bg_card`, иконки в кругах, акцент `@color/accent`,
  кнопки `Widget.Oda.Button`; индикатор серый/зелёный/красный (README, «Дизайн»). Новые экраны — в том же стиле.
- Дизайн бота утверждён; новые экраны бота — в том же стиле: `<b>Заголовок</b>`, пункты, синяя кнопка — главное
  действие, зелёная — пробный день/продление, красная — опасное. Приложение — чёрно-белое, листы снизу.

## Проверка
```bash
cd bot/worker && npm ci
npx tsc --noEmit        # типы
npm test                # имитация: локальный воркер + поддельный Telegram, 39 сценариев
cd ../.. && bash scripts/test-license.sh   # Ed25519 (RFC 8032) и License.java против кода подписи сервера
```
Имитация (`test/run.mjs`): пользователи и администратор «boss» (ADMIN_IDS=1999) шлют команды и жмут кнопки через
webhook, «телефоны» зовут `/v1/activate` и `/v1/check` (с `vpn`); время ключа и блокировок сдвигается через
`wrangler d1 execute --local`. Новый экран — функция в `views.ts`/`admin.ts`, ветка в `handlers.ts`/`Admin.callback`,
сценарий в `test/run.mjs`. Новая колонка или таблица — новая миграция `migrations/000N_….sql` (не править старые).
APK собирается только в CI (здесь нет Android SDK): после правок Java — пуш и workflow «Build APK».

## Развёртывание
`cd bot/worker && CLOUDFLARE_ACCOUNT_ID=3cc3b8392c90e87c7bc726e6b2c5fb9b CLOUDFLARE_API_TOKEN=… BOT_TOKEN=… bash deploy.sh`
— миграции, воркер, секреты (`LICENSE_KEY` не перезаписывается), webhook, меню (с `/admin` у администраторов),
описание бота. Токены — только у владельца (попросить в чате), не в репозиторий и не в файлы. Проверка после:
`/health`, `getWebhookInfo` (url `…/tg`, нет `last_error_message`), запрос с неверным ключом → `not_found`.
