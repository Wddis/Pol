# Уроки монтажа T2x2

## Журнал проверки рендера

- Пиши в `runs/<выпуск>/monitoring.log` время UTC и последние записи активного запуска каждые 240 секунд. Используй отдельный журнал для каждой попытки, чтобы старый `STOP` или `DELIVERY` не завершил наблюдение раньше времени.
- Привязывай наблюдение к PID конкретного запуска. Останавливайся по `STOP`, `DELIVERY` или завершению процесса и сохраняй последнюю запись. Фоновый журнал сам по себе не отправляет уведомления в чат.
- `RENDER: ok` подтверждает сборку, `QA` — завершение проверки. Для выдачи проверь список ошибок в свежем `qa.json` и статус `DELIVERY`. Сверяй время QA с текущим рендером: отчёт предыдущей попытки может ещё лежать в папке.

## Отправка на YouTube через BrightBean

- Сохраняй утверждённое превью отдельным файлом в папке выпуска. Перед отправкой проверь размер: для YouTube нужен файл до 2 МБ. При превышении подготовь JPEG 1280×720 и проверь читаемость текста.
- Сверь главы по финальному EDL и мастеру. Первая начинается с 0:00, каждая длится минимум 10 секунд.
- Для большого MP4 используй загрузку частями и финализацию с ETag каждой части. Сохрани ID медиа и публикации. При ошибке превью обнови существующий черновик и отправь его повторно с ключом идемпотентности.
- Статус `publishing` означает, что сервис принял отправку. Фиксируй публикацию после статуса `published` и получения ссылки YouTube.

- Сначала архивный план. Чужие нарезки часто используют другую шкалу времени.
- Проверяй границы по кадрам и звуку VOD. Архивное удаление TTS может оставить плашку в кадре.
- AAC нужен запас по true peak. Проверяй оба готовых AAC и идентичность пакетов.
- У каждого FFmpeg должны быть тайм-аут и ограниченная длительность. При живом вводе ставь сетевой тайм-аут.
- FFmpeg следует подавать аудио в Whisper через PCM, если API PyAV версии расходится с декодером Whisper.
- Кешируй звук и видео отдельно. После правки цензуры собирай звук и мультиплексируй существующее видео.
- HLS может заявлять 60 fps, хотя начало записи содержит рекламу 30 fps. Измеряй реальную частоту внутри выбранного игрового отрезка.
- Поиск плашки веди по изображению. В разных раскладках стрима одна и та же плашка может менять высоту.
- Локальный анализ готовит материал для оценки 18+ и музыки. Решения YouTube доступны владельцу в Studio.

## Разбор выпуска №2, 25.11.2026

Первый проход по ролику на 7:55 занял около 24 минут: подготовка 13:00, сборка 3:05, QA 7:41. QA удержал выдачу из-за пропусков маски при вращении баннера и восьми слов, которые ASR продолжил распознавать после правок. Эти слова надо перепроверять на слух: ASR может достроить обрывок из контекста.

- До кодирования прогони трекер на сменах креатива и поворотах плашки. Сохрани покадровые маски и одну контактную сетку пропусков. Восстанавливай контур по кадрам до и после пропуска. Сверяй индексы масок с первым кадром каждого чанка после seek.
- Проверь окна цензуры на обработанном аудио до сборки MP4. Сопоставь находку с исходным словом по EDL и прослушай короткий фрагмент. При необходимости уточни границу внутри слова и повторно проверь только изменённые окна. Сохраняй обрыв без бипа.
- После исправления маски пересобери только изменённые чанки. После правки цензуры пересобери AAC и подставь его в готовые видеопотоки через stream copy. Заново замерь true peak на итоговых файлах и сравни длительность и число кадров.
- Перед выдачей проверь кадры с исправленной маской и все спорные окна. В отчёте отдельно укажи результаты QA и недостающие метаданные. При повторном запуске сохраняй прежний мастер до проверки новой сборки.
- Если число срабатываний ASR выросло после правки, сопоставь их с предыдущим проходом по интервалам, а не по счётчику. Проверяй как совпавшие слова, так и новые находки между существующими окнами. Смещение ASR уточняй по исходному аудио.
- Для короткого провала трекера проверь кадры внутри интервала между двумя уверенными детекциями. Объединение соседних рамок — кандидат на маску, который нужно проверить на покрытие и выход за контур. Заполненное поле маски само по себе не подтверждает покрытие.
