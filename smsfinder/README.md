# SMS Finder

Подбирает виртуальные номера сразу на нескольких сайтах, проверяет, что номер живой
и принимает SMS от нужного сервиса, выдаёт лучший, ждёт SMS и присылает код
(в веб-интерфейс, в консоль и, по желанию, в Telegram).

## Проверка в процессе работы

1. **Этап 1 — быстрый отсев (секунды).** Каждый номер проверяется параллельно: страница/API
   отвечает, номер не снят и лента не в архиве, последнее SMS не старше суток, номер не
   выдавался ранее (реестр `~/.smsfinder/used.json`). Нерабочие отсекаются сразу с причиной.
2. **Этап 2 — живая проверка (`--probe`, по умолчанию 20 с).** Лучшие номера перепроверяются
   дважды; перестал отвечать — отсекается; пришло новое SMS — метка «живой».
3. **Сторожевой таймер во время ожидания.** Номер перепроверяется каждые 30 с и при 3 ошибках
   подряд; если он «умер», скрипт сам переключается на следующий из резерва. Кнопка
   «Другой номер» делает то же вручную.

## Telegram и другие «строгие» сервисы

Анализ 100 публичных номеров и схемы Telegram API (Telethon, `api.tl`) показал, почему коды
Telegram на публичных номерах часто «не подходят»:

* `auth.sentCodeTypeApp` — если на номере уже есть аккаунт, Telegram шлёт код **в приложение
  владельца**, а не SMS. Во входящих в это время видны только чужие коды.
* `sentCodeTypeFirebaseSms` / `sentCodeTypeSetUpEmailRequired`, ошибки `PHONE_NUMBER_BANNED`,
  `SESSION_PASSWORD_NEEDED` — новый аккаунт требует проверки устройства/email, номер в бане,
  на чужом аккаунте стоит пароль.
* На один номер одновременно запрашивают код несколько человек — коды перемешиваются.

Что делает скрипт для `--service telegram`:

1. **Отбор:** номер проходит, только если Telegram **уже присылал SMS** на него (значит, доставляет);
   номера без SMS от Telegram отсеиваются. Если код Telegram приходил за последние 15 мин —
   номер «занят» другим человеком и понижается.
2. **Код:** принимаются только SMS в формате Telegram (`Telegram code 12345`, `Telegram code: 123456…`,
   `Код для входа в Telegram`); коды других сервисов игнорируются. Показываются **все** коды,
   пришедшие после выдачи номера, со временем прихода; самый свежий отмечен ★; если кодов
   несколько — предупреждение о конкуренции. Номер продолжает слушаться и после первого кода.
3. **Отзыв:** «✓ Код подошёл» / «✗ Не подошёл» с причиной (код ушёл в приложение, неверный,
   заблокирован, просит email). «Не подошёл» навсегда убирает номер и сразу выдаёт следующий.
4. **Остановить** навсегда убирает номер из выдачи, пула проверенных и наблюдения.
   Реестр (`used.json`) на сайте сохраняется между перезапусками через `actions/cache`.

Честно: публичные номера для Telegram — лотерея. Надёжно работают приватные номера
(5sim и т.п., продукт `telegram`, у них в списке виден % доставки) или официальные анонимные
номера Telegram (+888) с fragment.com.

## Производительность и точность (последнее обновление)

* Новый источник **asms.ai**: ~240 номеров за 1,3 с, у 45 из 60 проверенных были SMS от Telegram
  (источник и разметка — из GitHub-проектов Shelex/free-otp-api, AbirHasan2005/OPRecon; парсер
  receive-smss.com восстановлен по 1d8/sedoppkit).
* **Меньше ложных «рабочих»:** SMS от Telegram в истории засчитывается, только если ему меньше
  суток; в карточке видно, сколько часов назад Telegram доставлял SMS.
* **Тест быстрее:** проверяются до 40 номеров одновременно, первыми — куда Telegram писал недавно;
  тест останавливается, как только найдено нужное число проверенных
  («найти 1 / 3 / 5 проверенных»). Фоновое наблюдение — до 60 номеров, опрос раз в 30 с параллельно.
* **Раздельные таблицы:** «✅ Проверенные» (SMS сервиса пришло при нашем наблюдении) и
  «🔎 Найденные, ещё не проверены». Номер переезжает в «Проверенные» на лету.
* После «Остановить» карточка номера с «Другой номер» исчезает.

## Веб-интерфейс

Одна кнопка **«Подобрать номер для <сервис>»**. Под ней видно, что происходит: три этапа
(1 — отсев нерабочих, 2 — живая перепроверка, 3 — тест доставки сервиса), полоса прогресса,
счётчики «проверено / подходят / отсеяно / прошли тест», последний проверенный номер и время.
Номера показываются сразу после этапа 2, тест доставки обновляет строки на лету; рекомендуемый
номер вынесен наверх (номер, где код сейчас запрашивает кто-то другой, не рекомендуется).
«Тест доставки сервиса»: без теста / 3 номера до 3 мин / 5 до 5 мин / 8 до 10 мин.

### Почему подбор больше не обрывается

Раньше прогресс шёл одним длинным потоком событий (SSE). Замеры показали, что Cloudflare-туннель
отдаёт такой поток браузеру **целиком в конце** (все 47 событий пришли разом через 11,8 с, локально —
по одному с 0,0 с), а «молчащее» соединение рвёт примерно через 100 с. По исходникам
cloudflared (`connection.go: shouldFlush`) сам клиент туннеля поток не держит — буферизует край
Cloudflare. Поэтому теперь подбор — **фоновая задача на сервере** (`POST /api/search`), а страница
раз в секунду забирает новые события (`GET /api/search/<id>?after=N`). Обрыв связи, сон телефона
или перезагрузка страницы подбор не прерывают — страница просто подхватывает его снова.

Ускорение: «мёртвые» номера (архив, нет SMS) запоминаются на час и не перепроверяются; если сайт
начинает ограничивать запросы (403/429), его оставшиеся номера пропускаются сразу; живая
перепроверка — 10 с вместо 20; фоновый пул берёт номера из ваших подборов и не запускает
параллельный поиск. Подбор без теста — 3–6 с.

## Подтверждение доставки — категория «проверенный»

**Тест идёт под выбранный сервис.** Номер ставится под наблюдение: запоминаются все SMS во
входящих, и номер становится «проверенным для Telegram», только если во время наблюдения
приходит **новое SMS именно от Telegram** (в формате «Telegram code …»). SMS других сервисов
записываются как доказательство для них (VK, Google…), но для Telegram не засчитываются. Номер
получает статус «проверенный»; сохраняются отправитель, отпечаток SMS и время с начала
наблюдения. Подход взят из github.com/LayorX/Temporary-SMS-Receiver-Monitor.

**Фоновый пул.** Веб-интерфейс постоянно наблюдает ~24 лучших номера (обновление списка
каждые 15 мин, опрос раз в минуту) и складывает подтверждённые в «Пул проверенных номеров».
Отключается `SMSFINDER_WATCH=0`.

**Активный способ.** Если подключён свой шлюз, на номер уходит SMS со случайным кодом
(`SMSFinder check 482913`), и скрипт ищет его во входящих. Если шлюз не смог отправить,
проверка автоматически переходит на пассивную.

```bash
python -m smsfinder find --mode verified --verify 4 --verify-wait 300 -v
python -m smsfinder find --mode verified --verify-method active --verify 1
```

Почему не «бесплатная отправка SMS»: на GitHub бесплатных API для отправки на чужие
номера нет — есть шлюзы через ваш телефон (ниже) и «SMS-бомберы», которые заставляют
чужие сайты слать свои коды. Последнее — злоупотребление чужими сервисами, здесь не используется.

Шлюзы отправки (первый настроенный):

| Шлюз | Переменные | Примечание |
|------|-----------|-----------|
| textbee ([github.com/textbee/textbee](https://github.com/textbee/textbee)) | `TEXTBEE_KEY`, `TEXTBEE_DEVICE` | open-source, бесплатный тариф, SMS уходит с вашего Android |
| httpSMS ([github.com/NdoleStudio/httpsms](https://github.com/NdoleStudio/httpsms)) | `HTTPSMS_KEY`, `HTTPSMS_FROM` | open-source, тоже через ваш Android |
| Twilio | `TWILIO_SID`, `TWILIO_TOKEN`, `TWILIO_FROM` | платный |
| Textbelt | `TEXTBELT_KEY` | без ключа — 1 SMS/день, но бесплатно для США/Канады отключено |

## Режимы

| Режим     | Что выдаёт |
|-----------|------------|
| `verified` | только номера, до которых реально дошло тестовое SMS |
| `niche` (по умолчанию) | только **нишевые** (выбранный сервис на номере ещё не регистрировался, мало SMS/сервисов, редкие страны в приоритете) и **премиум** |
| `premium` | только приватные платные номера: реальная SIM или доставка ≥ 50%, номер новый для сервиса |
| `popular` | все рабочие номера, сортировка по активности |

## Источники номеров

| Провайдер     | Тип                      | Что проверяется при подборе                                    | Ключ |
|---------------|--------------------------|----------------------------------------------------------------|------|
| asms.ai (anonymsms) | бесплатный, публичный, **новые номера** (/new-numbers), ~240 номеров, точное время SMS | время каждого SMS, был ли сервис и когда |  —  |
| receive-smss.com | бесплатный, публичный (за Cloudflare; с части IP — 403, тогда пропускается) | история SMS | — |
| freephonenum.com | бесплатный, публичный, редкие страны | статус ленты (Live/архив), число SMS и сервисов, был ли сервис |  —  |
| receivesms.co | бесплатный, публичный    | последняя активность, кол-во SMS за 24 ч, приходили ли SMS от сервиса | —    |
| onlinesim.io  | бесплатный, публичный    | статус номера, свежесть, приходили ли SMS от сервиса           | —    |
| 5sim.net      | платный, приватный       | % доставки по оператору, наличие, цена (публичное guest-API)   | `FIVESIM_API_KEY` |
| SMS-Activate-совместимые (Grizzly SMS и др.) | платный, приватный | наличие, цена | `SMSACT_KEY`, `SMSACT_URL` |

Все провайдеры опрашиваются параллельно, номера каждого провайдера проверяются
в пуле потоков, результаты сводятся в один рейтинг (score).

> Публичные бесплатные номера видят все: SMS на них читает любой, а номер может быть
> уже привязан к чужому аккаунту. Для своих аккаунтов берите приватный платный номер.

## Запуск

```bash
pip install -r requirements.txt

# консоль
python -m smsfinder find --service telegram --mode niche -v
python -m smsfinder get  --service telegram --mode niche --pick 1 --timeout 600

# веб-интерфейс на http://localhost:8000
python -m smsfinder.web
```

## Переменные окружения

| Переменная          | Назначение |
|---------------------|-----------|
| `FIVESIM_API_KEY`   | ключ 5sim.net — покупка номеров |
| `SMSACT_KEY`        | ключ SMS-Activate-совместимого сервиса |
| `SMSACT_URL`        | адрес `handler_api.php` (по умолчанию Grizzly SMS) |
| `TELEGRAM_TOKEN`, `TELEGRAM_CHAT_ID` | пересылать пришедшие SMS в Telegram |
| `SMSFINDER_TOKEN`   | закрыть веб-интерфейс: доступ только по `?t=<токен>` |
| `PORT`              | порт веб-интерфейса |

Если веб-интерфейс доступен из интернета и заданы ключи платных провайдеров,
обязательно задайте `SMSFINDER_TOKEN`: иначе любой, у кого есть ссылка, сможет
покупать номера за ваш счёт.

## Как это устроено

- `providers/` — по модулю на сайт: `find()` ищет и проверяет номера,
  `acquire()` занимает номер, `messages()` читает SMS, `release()` завершает/отменяет активацию.
- `engine.py` — параллельный подбор, рейтинг, ожидание SMS в фоновом потоке.
  Для публичного номера запоминаются уже пришедшие SMS и показываются только новые.
  Платная активация без кода по таймауту отменяется (деньги возвращаются провайдером).
- `web.py` + `static/index.html` — веб-интерфейс; `cli.py` — консоль.

Идеи и форматы API взяты из открытых проектов: `tezmen/python-sms-activate-ru`,
`ErikPelli/fivesim`, `enescingoz/5sim_ui`.

## Временный сайт через GitHub Actions

Workflow `.github/workflows/smsfinder-preview.yml` запускается при push (или вручную,
Actions → smsfinder-preview → Run workflow), поднимает веб-интерфейс на раннере и открывает
публичный адрес `https://*.trycloudflare.com`. Адрес виден в заголовке проверки job'а,
в его логе (`PREVIEW_URL=`) и в Summary. Сайт живёт до ~5 ч или до отмены run'а.
Ключи платных провайдеров можно передать через Secrets: `FIVESIM_API_KEY`, `SMSACT_KEY`
(тогда задайте и `SMSFINDER_TOKEN`).
