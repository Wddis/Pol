# Регламент быстрых инструментов (16.11.2026) — скорость БЕЗ потери качества и стабильности

Порядок основного видео (≈ 25–35 мин на час события вместо 1,5–3 ч):
1. **Расшифровка** — `tools/stt.py` (faster-whisper batched, ~27× реального времени). Не менять на whisper.cpp/WhisperX:
   на CPU не быстрее (проверено по GitHub 16.11).
2. **Донаты** — `tools/donations.py TRANSCRIPT FROM TO`: список донатов с ответом (CUT?/KEEP). Я ПОДТВЕРЖДАЮ каждый вырез
   глазами (ложные срабатывания на вопросах из видео бывают). 16.11 нашёл пропущенный вручную донат.
3. **Промокоды в чате** — `tools/chat_promo_mask.py ev.mp4 mask.mkv --region <чат>`: покадровая маска по бордовой
   подсветке промо-сообщений (20 fps, минуты на час). В план: `"mask": {...}`. НЕ использовать сотни таймбоксов
   (`chat_promo_scan.py`) для рендера: 191 бокс = многократно медленнее и боксы «съезжают» при прокрутке чата.
   Регион = РАМКА ЧАТА (по кадру, напр. 1630,90,290,900) — иначе ловит красное в самом видео.
4. **Рендер** — `tools/edit2.py` (2 задания, x264 veryfast crf20): ≈ 10–15 мин на 50 мин видео. Качество не трогаем
   (пресет/crf не понижать).
5. **Интро + превью + референсы** — параллельно: `add_intro.sh`, превью 640x360 (≤ 150 МБ), `tools/cover_refs.py`
   (СТРОГО по `docs/cover-refs.md`: обложка оригинала обязательна).
6. Всё сразу: `tools/make_main.sh VOD FROM TO "вырезы" ИМЯ` — шаги параллельно, перезапуск продолжает с места сбоя.

Блюр: баннеры — `[1610,8,302,102]` и `[0,0,268,108]` (строго в рамке, docs/montage-style.md), промо в чате — маска.

Стабильность:
- Две тяжёлые задачи на 4 ядрах НЕ запускаем одновременно (рендер ∥ рендер) — только очередью.
- Каждый шаг пишет лог; провал → читаю лог, чиню инструмент, коммичу, перезапускаю только упавший шаг.
- Перед публикацией: кадр с чатом (промо размыты, остальное чисто), длительность, звук, тайм-коды (`timecodes.py`).

## Звук (16.11.2026)
`tools/norm_audio.py in out` — двухпроходная нормализация: замер → одна постоянная прибавка (volume) + пиковый лимитер −1.5 dB, 48 кГц
(loudnorm linear=true молча становится динамическим, если пики исходника у 0 dBTP — так у T2x2 почти всегда), видео
копируется. Используется в конце `edit2.py` и `shorts_render2.sh`. Однопроходный loudnorm не использовать (качает звук).

## Шортсы (16.11.2026)
`tools/shorts_qc.py src SRC.mp4 "s-e …"` до рендера (чёрные/зависшие кадры экрана + полосы краёв кропа вебки для проверки
глазами) и `tools/shorts_qc.py out OUT.mp4` после (1 аудиопоток, 48 кГц, −14±1 LUFS, пик ≤ −1). Секунды на шортс.
Переделка хвоста длинного рендера — из сохранённых кусков (hardlink `out.mp4.parts`), не с нуля.
