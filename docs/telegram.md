# Telegram через пульт (17.11.2026)

Владелец входит в Telegram Web (web.telegram.org/k) через пульт `remote_browser.js`. Вход — по QR-коду или номеру телефона,
вводит только владелец. Дальше Claude работает в той же вкладке через CDP: `tools/tg/tg_web.js`.

## Поднять пульт на Telegram
```
S=<scratchpad>; cd $S
: > empty_cookies.txt                       # cookies для Telegram не нужны
python3 -c "import secrets;print(secrets.token_urlsafe(18))" > rb_token
RB_TOKEN=$(cat rb_token) setsid nohup node <repo>/tools/yt/remote_browser.js empty_cookies.txt 8765 9222 \
  "https://web.telegram.org/k/" > rb.log 2>&1 < /dev/null &
curl -s -o qr.png "http://127.0.0.1:8765/shot?t=$(cat rb_token)"   # экран с QR → владельцу
```
QR-код живёт ~30 с: присылать свежий (вырезать квадрат из скриншота). Владелец: Telegram → Настройки → Устройства →
Подключить устройство. Для живого пульта с телефона — Dev Tunnels (docs/publishing-methods.md).

## Сохранить вход (сразу после входа)
`node tools/tg/tg_web.js session-save $S/tg_session.json`. Вход хранится в localStorage (`dc*_auth_key`, `user_auth`).
Файл — это ПОЛНЫЙ доступ к аккаунту: только scratchpad, не в репо, не в лог. После перезапуска контейнера:
поднять пульт (как выше), затем `tg_web.js session-restore $S/tg_session.json` — без нового QR.
Отозвать доступ владелец может в Telegram → Устройства (сессия «Telegram Web, Linux»).

## Анализ каналов — `tools/tg/tg_channel.js` (только чтение, ничего не сохраняет)
Работает через внутренний API Telegram Web (`rootScope.managers.apiManager`) в той же вкладке: ~100 постов за 0,5 с,
поиск на сервере. Чаты не открывает, прочитанными не отмечает, ни на что не подписывается. Печатает только подходящие посты,
по 2 строки: `дата МСК 👁просмотры ↗репосты ❤реакции [тип] ссылка` + текст (обрезан до `--chars`).
```
tg_channel.js info  @gta_5                                  # подписчики, число постов, описание
tg_channel.js scan  @gta_5 --q трейлер --days 14            # серверный поиск — сначала он, режет объём
tg_channel.js scan  @a,@b,@c --re "розыгрыш|giveaway" --not "erid|реклама" --days 7
tg_channel.js scan  @gta_5 --days 30 --top 10 --by views    # лучшее вместо ленты (views|fwd|react|replies|er)
tg_channel.js stats @gta_5 --days 7                         # постов/день, просмотры ср/медиана, ER, типы, часы, домены, теги, топ-5
tg_channel.js find  "розыгрыш PS5" --days 2 --limit 30      # по ВСЕМ каналам/чатам аккаунта
```
Фильтры: `--min-views N`, `--media photo|video|document|rich|none`, `--links`, `--since/--until ДАТА`, `--limit N`
(по умолчанию 300 на канал), `--chars 0` — полный текст, `--json FILE` — выгрузка в scratchpad. Альбом — одной строкой.
Новые «rich»-посты (без поля message) читаются из блоков — тип `[rich]`.

## Архив — `tools/tg/tg_archive.js` (только по команде владельца)
Без `--yes` — пробный прогон: показывает каждый канал и где он сейчас (`→` будет перенесён, `=` уже на месте,
`✗` не найден). Больше ничего не трогает: не отписывается, не глушит, не отмечает прочитанным.
```
tg_archive.js list                                    # что в архиве (всего N)
tg_archive.js archive @a @b t.me/c -1905100403        # пробный прогон
tg_archive.js archive --file список.txt --yes         # из любого текста: все @username и t.me/… ссылки
tg_archive.js unarchive @a --yes                      # вернуть в общий список
```
Переносит пачками по 100 одним запросом (`folders.editPeerFolders`).

## Опыт
- Escape в Telegram Web открывает режим поиска, а не закрывает окна — инструмент возвращается к списку кнопкой «назад».
- Окно подсказки «Appearance» после входа невидимо перекрывает клики — инструмент закрывает его сам.
- Открыть чат = прочитать его у владельца (как в обычном клиенте). Чужие чаты без нужды не открывать.
- `messages.getDialogs` с папкой «Архив» присылает и закреплённые чаты общего списка — фильтровать по `folder_id`.
- Новый вид постов: текст лежит в `rich_message.blocks`, а `message` пустой.
- `b.close()` при CDP-подключении только отключается, браузер пульта продолжает работать.
