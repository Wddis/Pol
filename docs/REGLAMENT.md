## 2. Правила владельца (действуют всегда)
- **Без зума** (12.11, урок Steam Frame 18+). Код зума сохранён (`ALLOW_ZOOM=1`) — только по прямой команде.
- **Вебку не блюрим никогда.** Начало/конец события не режем.
- **Интро «Ретро-ТВ»** (10 с) — на каждом основном видео, не на шортсах.
- **Блюр строго в рамке**: баннеры `[1610,8,302,102]` (FONBET справа сверху) и `[0,0,268,108]` (виджет доната).
- **Промокоды в чате НЕ блюрим (приостановлено 16.11)** — скорее всего, на 18+ не влияют. Инструмент маски остаётся
  (`PROMO=1 make_main.sh …` включает), правило «только окошко сообщения» — если вернём.
- **Мат глушим (с 16.11)**: `tools/mat_mute.py` — по умолчанию в `make_main.sh` и `shorts_render2.sh` (`MAT=0` выключает).
  Отчёт `mat_report.txt` — проверить 3–5 мест. Пруф: см. п. 7.
- **Название основного видео — с 16.11**: `T2x2 СМОТРИТ: <название оригинала>` / `T2x2 ИГРАЕТ В <игру> / <Original>` —
  кто и что делает видно сразу в ленте; хук в начале и «/ РЕАКЦИЯ T2x2» в конце больше не ставим (docs/montage-style.md).
- **Шортсы — дизайн v2 «clean»** (12.11). Интервал публикации 10 мин, ≤ 3–4 загрузок в сутки на канал.
- **Публикация только по команде владельца**, обложка — владельца. Ссылку «Полное видео» в шортсы — после публикации основного.
- **Референсы обложки — строгий набор** (docs/cover-refs.md): обложка оригинала (для реакций обязательна), лицо ×8,
  вырезки ×4, кадры экрана ×4, sheet + zip. Для игр — `--game` (обложки оригинала нет).
- **Вместе с превью всегда присылать название, полное описание с тайм-кодами и теги** (16.11: «не прислал название и описание»).

## 3. Качество шортсов (16.11.2026, по замечаниям владельца)
- **Звук** — только `tools/norm_audio.py` (замер → одна постоянная прибавка + пиковый лимитер, −14 LUFS, −1.5 dB, 48 кГц).
  Однопроходный `loudnorm` «качает» звук (давится на криках), а `linear=true` у T2x2 молча становится динамическим
  (пики исходника у 0 dBTP). Без `-ar` получался 96 кГц.
- **Экран** — кроп по ЦЕНТРУ кадра: игра на весь экран `SCR=1264:711:328:0`, браузер с видео `SCR=1192:670:364:40`
  (без панели браузера). Левый край кадра (старый 1150:647:0:112) срезал картинку набок.
- **Вебка** — кроп строго внутри окна вебки: окно T2x2 x≥1298, y≥712 → `CAM=620:349:1300:716`. Старый 655:368:1265:712
  тащил в карточку вебки полосу игры. Проверка — увеличенные полосы краёв (`shorts_qc.py src` → `qc_cam_*.png`) глазами.
- **Чёрные экраны загрузки/меню** — вырезать (`shorts_qc.py src` показывает BLACK); границы — по расшифровке, речь не резать.
  FREEZE на реакциях (стример поставил видео на паузу) — норма.
- После рендера `shorts_qc.py out`: 1 аудиопоток, 48 кГц, −14±1 LUFS, пик ≤ −1 dBFS. Плюс 4 кадра глазами.

## 4. Скорость и стабильность (docs/tools-speed.md)
- Две тяжёлые задачи на 4 ядрах одновременно НЕ запускать (рендер ∥ рендер) — очередь.
- Рендер не ускорять ценой качества (пресет/crf не понижать). Ускорение — за счёт: маски вместо сотен таймбоксов (2×),
  пакетного whisper (27×), параллельных лёгких шагов, возобновляемых скриптов.
- Длинный рендер, который нужно переделать на хвосте (звук, интро), — не перезапускать с нуля: готовые куски
  `out.mp4.parts/*.mp4` сохранить (hardlink), склеить `-c copy` и доделать только хвост (16.11: сэкономлено ~25 мин).
- Каждый шаг пишет лог; упал → читаю лог, чиню инструмент, коммичу, перезапускаю только упавший шаг.
- Фон — `setsid nohup`; контейнер может перезапуститься (файлы живут, процессы — нет).
