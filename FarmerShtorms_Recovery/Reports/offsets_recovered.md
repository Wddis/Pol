# Уцелевшие оффсеты (Phase 1.1)

## ⚠️ Поправка к Phase 1
Файл **не обнулён**, а **сдвинут**: где-то в rodata, ориентировочно между 0x1BD0000 и 0x30F3400, из него **выпали 1999 байт**. Всё, что лежит после этой точки, смещено на −1999 (0x7CF). Из этого следуют три вещи:
- конец файла короче ровно на эти байты, поэтому таблица секций «за пределами файла»;
- DYNAMIC целый: он лежит по смещению `0xc89fc28 − 1999 = 0xc89f459`;
- нулевые блоки в RW-сегментах — **нормальные данные**: слоты под RELATIVE-релокации и инициализированные нулями массивы. Это не повреждение.

Формула: **file_offset = vaddr − 0x4000 − 1999** для кода и всех данных после точки разрыва; **file_offset = vaddr** для заголовков, .dynsym/.dynstr, таблиц релокаций и начала .rodata.
Проверка: `JNI_OnLoad` (vaddr 0x5ac3bf0) → файл 0x5abf41f: `ff c3 00 d1` = `sub sp, sp, #0x30`, корректный пролог ARM64.

## Чего по-прежнему нет
**Имён для 627 811 функций нет.** Адрес каждой функции известен, но какая из них `WeaponShop.Buy`, а какая `PhysX::raycast`, без `global-metadata.dat` не сказать: IL2CPP хранит соответствие «метод → индекс → адрес» в метаданных и CodeRegistration.

3. С `global-metadata.dat` той же сборки — Il2CppDumper/Cpp2IL для получения имён.
