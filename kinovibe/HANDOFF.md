Владелец общается по-русски, коротко. Всё оформление — по `STYLE.md`, этот файл — «что где лежит и как всё восстановить».

## 1. Что за проект

**КиноВайб** — записи стримов Twitch, где стримеры смотрят фильмы и сериалы, с реакцией стримера.
Площадки: Telegram-канал (основная, полные записи) и TikTok (короткие моменты, ведут в Telegram).

### Доступ к аккаунту (каждая новая сессия)
1. Клиент: папка `tg/` из ветки `ccr-a37e2040-aq2eun` (`git show origin/ccr-a37e2040-aq2eun:tg/tg.js` и т.д.), `npm install` (GramJS через WebSocket `*.web.telegram.org`).
2. Нужны переменные `TG_API_ID`, `TG_API_HASH` (my.telegram.org). Если их нет в окружении — спросить владельца. **В репозиторий не класть.**
3. Вход: `NODE_EXTRA_CA_CERTS=/root/.ccr/ca-bundle.crt node tg.js qr` → `qr.png` обновляется каждые ~30 с, сразу отправлять владельцу; он сканирует: Telegram → Настройки → Устройства → Подключить устройство. Сессия — `session.txt` (**не коммитить**).
4. Скрипты запускать как `node tg.js run <script.js>` из рабочей папки, куда скопированы `kinovibe/*.js`, `posts.json`, `covers_done.json`, `covers/`.

### Рабочий цикл для новой партии постов (подробно — STYLE.md §4–§7)
1. Посмотреть новые посты (id, альбомы, пересланные ли, подписи владельца).
2. Стример: ник проверять через Twitch GQL (`gql.twitch.tv`, Client-Id `kimne78kx3ncx6brgo4mv6wki5h1ko`, `user(login:"…"){displayName followers{totalCount}}`). Не угадывать — если не подтверждён, спросить.
3. Фильм: Wikidata (IMDb id P345, Kinopoisk id P2603, длительность P2047) → рейтинги `https://rating.kinopoisk.ru/<kp>.xml`.
4. `new.json` → (`REPOST_FROM=…`) `repost_styled.js` для пересланных постов и для разделения альбомов с несколькими фильмами → `style_posts.js` → каталог (`catalog_page.js`/`telegraph_page.py`) → `make_covers.py` → `apply_covers.js`.
5. Проверить: у каждого видео есть обложка, у каждого поста — комментарии, ссылки каталогов живые.

### Договорённости с владельцем
- Описание фильма — **цитатой** (blockquote), без спойлеров; ник стримера — **точный с Twitch**, со ссылкой и хэштегом.
- Рейтинги — IMDb и Кинопоиск (не TMDB), сверенные по базе, не по памяти. Ошибки в исходных подписях (год, название) исправлять.
- Не писать про «общественное достояние» и юридические пометки.
- Разные фильмы в одном альбоме («Тачки 1–3») → каждый фильм отдельным постом; части одного фильма — один альбом.
- Публиковать с паузой 10–15 с (иначе у постов нет ветки комментариев); при FLOOD — ждать (скрипты делают это сами).
- Пересланные посты нельзя редактировать → перевыкладывать как свои (`repost_styled.js`).
- Claude **не скачивает и не перезаливает чужие полные записи фильмов** в канал сам (только оформляет то, что публикует владелец).

## 5. Buffer (постинг в TikTok)

| Что | Значение |
|---|---|
| Кабинет | https://publish.buffer.com/channels/6af35ed662b70b94b0e6430d/schedule |
| API | GraphQL `POST https://api.buffer.com`, заголовок `Authorization: Bearer <ключ>` |
| Организация | `6af35dd6f71fd9215f39b2bf` («My organization») |
| Каналы | `6af35ed662b70b94b0e6430d` — TikTok `kinovibetwitch`; `6af3934362b70b94b0e99c8d` — YouTube «Фильмы со стримерами» (Shorts) |
| Регламент | каждый ролик — одновременно TikTok + YouTube Shorts (с 11.11.2026), см. `tiktok/TIKTOK_STYLE.md` |
| Ключ | **НЕ в репозитории** (репозиторий публичный). Сохранён как секрет окружения для хоста `api.buffer.com` — прокси подставляет его сам; в скриптах можно передавать любой фиктивный `BUFFER_TOKEN`. Если секрета нет — попросить владельца (через форму request_credential, не в чат). |

Помощник: `buffer.sh '<graphql>' '<variables json>'`. Примеры:
```bash
./buffer.sh '{ account { organizations { id name } } }'
./buffer.sh 'query($o: OrganizationId!){ channels(input:{organizationId:$o}) { id name service } }' '{"o":"6af35dd6f71fd9215f39b2bf"}'
./buffer.sh 'query($o: OrganizationId!){ posts(input:{organizationId:$o, filter:{channelIds:["6af35ed662b70b94b0e6430d"]}}, first: 20) { edges { node { id status dueAt text } } } }' '{"o":"6af35dd6f71fd9215f39b2bf"}'
```
Пост: мутация `createPost(input: CreatePostInput)` — поля `channelId`, `text`, `assets` (видео **по публичному URL**: `url`, `thumbnailUrl`), `metadata.tiktok.title`, `schedulingType`, `mode`, `dueAt`, `saveToDraft`.
Видео Buffer забирает только по публичной ссылке → либо ссылка от владельца, либо нарезка из записи + загрузка на файлообменник **с согласия владельца**.
Первый шаг, о котором договорились: тестовый ролик сохранить в Buffer **черновиком** и показать владельцу.

## 5a. FastClip (нарезка клипов для TikTok)

- MCP-сервер `fastclip` прописан в `.mcp.json` репозитория (`https://api.fastclip.it/mcp`, HTTP).
  Токен (`fc_…`) **не в репозитории** — сохранён как секрет окружения для `api.fastclip.it`, прокси подставляет его сам.
  Сервер подключается при старте сессии (может спросить разрешение на проектный MCP — разрешить).
- Инструменты: `import_video` (видео по ссылке), `list_videos`, `get_transcript`, `get_moments`,
  `create_clip` (вырез start–end в секундах, рендер MP4 с кадрированием 9:16), `get_clip` (статус → `download_url`), `list_clips`.
- Связка с Buffer: `download_url` готового клипа — публичная ссылка на MP4 → её можно передать в `createPost` как видео для TikTok.
- Делать только клипы, которые попросил владелец (каждый клип расходует лимит аккаунта FastClip).
- Без MCP (в текущей сессии) можно вызывать тот же API через curl: JSON-RPC `initialize` → `tools/list` / `tools/call` на `https://api.fastclip.it/mcp`.
