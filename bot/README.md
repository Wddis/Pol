## Цель и связь с приложением ODA
**Ключ — это доступ к приложению ODA, а не к серверу подключения.** Подключение делает само приложение
(обход DPI, Psiphon, Tor — без своих серверов); ключ определяет, можно ли пользоваться приложением и сколько.

Путь пользователя:
1. В боте: «Купить ключ» (тариф и число устройств) или «Пробный день» → ключ `ODA-XXXX-XXXX-XXXX`.
2. Первый запуск ODA → экран «Введите ключ доступа» → приложение отправляет ключ на сервер ключей
   (`POST /v1/activate`) → сервер запускает срок с этой минуты, занимает место устройства и отвечает
   подписанной лицензией → ODA открывается.
3. ODA проверяет ключ при запуске и раз в сутки (`POST /v1/check`), лицензию хранит и проверяет подпись
   сама (работает и без связи с сервером, пока срок не вышел). Лицензия — `<данные>.<подпись>` (base64url без
   `=`), данные — JSON `{"dev","devices","exp","iat","key","tariff","v":1}` с ключами по алфавиту, подпись
   Ed25519 над байтами данных; `exp` — конец срока (unix-время сервера).
4. За 2 дня и за 1 день до конца — уведомление и плашка «Продлить в Telegram»; продление тем же ключом.
5. Срок вышел — VPN отключается, ODA показывает «Тариф закончился» и просит новый ключ (продлённый
   включается сам при следующей проверке).

**Сделано:** бот целиком и сервер ключей — две одинаковые версии: **Cloudflare Workers** (`worker/`, бесплатно,
круглосуточно, без своего сервера — основной вариант) и Python (`oda_bot/`, для VPS — `deploy/`). Экраны, кнопки,
API и лицензии у них совпадают один в один (проверяет `worker/test/parity.mjs`).
**Не сделано (следующие шаги):**
- экран ключа в приложении (Android): ввод, `/v1/activate` (`device_id` — 8–128 символов `A-Za-z0-9_-`,
  постоянный для установки; `device_name` — модель телефона), хранение лицензии, проверка подписи открытым ключом
  `OSkRbr2ENcvsYqTI8JiusLO3M6k9vXL5m9lHKu8kcB4`, проверка раз в сутки, уведомления за 2 и 1 день, блокировка
  подключения после срока (плитка в шторке тоже), тексты ошибок — из поля `message` ответа сервера;
- оплата (решено: пока без неё; варианты — Telegram Stars или карта/ЮKassa);
- адрес сервера ключей в приложении — `https://oda-vpn-bot.dimazoltinsky.workers.dev` (запасной — свой домен);
- ссылка «Скачать ODA» в боте (`APK_URL` в `worker/wrangler.toml`) и контакт поддержки (`SUPPORT`) — пока
  пустые: в боте «Ссылка на скачивание появится здесь» и «[КОНТАКТ ПОДДЕРЖКИ]»; в «Правилах» — `[УСЛОВИЯ
  ВОЗВРАТА]`, `[ВРЕМЯ ОТВЕТА]`.

**Решения, принятые с владельцем** (чтобы не обсуждать заново):
- тарифы 1 неделя / 1 месяц / 3 месяца; от 1 до 5 устройств, цена растёт с числом устройств; пробный день — 1;
- срок — с активации в приложении; предупреждения за 2 и 1 день; после срока — новый ключ;
- оплаты пока нет (`ODA_FREE_MODE=1`), цены в боте — «[ЦЕНА]»;
- иконки custom emoji на кнопках не нужны (требуют Telegram Premium) — только цвета кнопок;
- дизайн бота и экранов ключа утверждён.

**Риски, о которых сказано владельцу:** сеть Psiphon используется по её публичной конфигурации — платный
доступ к приложению может противоречить условиям Psiphon; в РФ запрещена реклама VPN (тексты бота —
нейтральные); токен бота был в переписке — перед постоянным запуском выпустить новый (`/revoke` в BotFather);
адреса `*.workers.dev` у части операторов РФ бывают недоступны или замедлены — тогда сервер ключей на свой домен
через Cloudflare (Workers → Settings → Domains & Routes), а приложению — запасной адрес и вход через свой обход DPI
(ответы сервера ключей меньше 16 КБ — замедление Cloudflare после 16 КБ им не мешает).

## Как устроено
- **Ключ** — `ODA-XXXX-XXXX-XXXX` (12 символов без похожих букв и цифр, ~57 бит — перебором не подобрать).
  Тарифы: 1 неделя, 1 месяц, 3 месяца; от 1 до 5 устройств (каждое сверх первого — +`ODA_EXTRA_DEVICE_PCT`%
  к цене); пробный день — один раз на аккаунт Telegram, 1 устройство.
- **Срок начинается с активации** — при первом вводе ключа в приложении, не при покупке. Продление — тем же
  ключом: к оставшемуся сроку, а если он вышел — с текущей минуты.
- **Устройства**: первый ввод на телефоне занимает место; когда места кончились — отказ с подсказкой.
  «Профиль → Сменить устройство» отвязывает все устройства ключа (срок не меняется).
- **Лицензия**: на активацию и проверку сервер отвечает подписанной (Ed25519) лицензией — ключ, устройство,
  тариф, срок. Приложение проверяет подпись открытым ключом, вшитым в него: срок считает сервер, а не часы
  телефона, и подделать лицензию без закрытого ключа нельзя.
- **Разделы бота**: меню, тарифы, ключ, пробный день, профиль (продление, смена устройства, мои ключи),
  приложение, о VPN (частые вопросы), как подключить, если не работает, конфиденциальность (что хранится и что
  нет), правила (`[УСЛОВИЯ ВОЗВРАТА]`, `[ВРЕМЯ ОТВЕТА]` — заполнить), поддержка.
- **Кнопки**: цвет (`style`: синяя — главное действие, зелёная — пробный день и продление, красная —
  «Отвязать все»). Иконки custom emoji не используются (нужен Telegram Premium у владельца): в версии на
  Python осталась выключенная возможность (`/icons`, `ODA_ADMIN_IDS`), в воркере её нет.
- **Оплата** пока не подключена (`FREE_MODE=1` / `ODA_FREE_MODE=1`): ключи и продления выдаются сразу. Оплата
  встанет в `handlers.ts`/`handlers.py` перед `createKey`/`extend`.

## Сервер ключей (для приложения)
| Запрос | Что делает |
|---|---|
| `POST /v1/activate` `{"key","device_id","device_name"}` | Ввод ключа: первая активация запускает срок, устройство занимает место. 200 — `{"status":"ok","license",…,"expires_at","days_left"}` |
| `POST /v1/check` `{"key","device_id"}` | Проверка (приложение — при запуске и раз в сутки): свежая лицензия или причина |
| `GET /v1/pubkey` | Открытый ключ подписи (base64url, 32 байта) |
| `GET /health` | Жив ли сервер |

Ошибки — `{"status":"<код>","message":"<текст для экрана>"}`: `not_found` 404, `revoked` 403, `expired` 410
(с `expires_at`), `device_limit` 409, `device_removed` 401, `bad_request` 400, `too_many` 429 (больше 10
неудачных вводов с адреса за 10 минут).

Сервер ключей должен открываться **из России без VPN**: при первом входе VPN ещё не работает. Cloudflare
Workers — HTTPS сразу; на VPS — через Caddy перед портом 8080.

## Бесплатно: Cloudflare Workers (основной вариант)
**Работает с 27.10.2026** (подробно — «Состояние» в начале): `https://oda-vpn-bot.dimazoltinsky.workers.dev` (аккаунт Cloudflare владельца, база D1
`oda-vpn-bot`). Webhook бота — `/tg`, сервер ключей — `/v1/activate`, `/v1/check`, проверка — `/health`.
**Открытый ключ лицензий** (вшить в приложение): `OSkRbr2ENcvsYqTI8JiusLO3M6k9vXL5m9lHKu8kcB4`.

Бот и сервер ключей — один воркер (`worker/`, TypeScript, без библиотек), база — Cloudflare D1 (SQLite).
Telegram сам присылает обновления на `https://<воркер>/tg` (webhook с секретом), поэтому сервер не нужен,
работает круглосуточно. Бесплатного тарифа хватает с большим запасом: 100 000 запросов в сутки, база до 5 ГБ.

Что нужно один раз (бесплатно, без карты):
1. Аккаунт на [dash.cloudflare.com](https://dash.cloudflare.com) → **Workers & Pages** → выбрать поддомен
   `*.workers.dev`. Справа на той же странице — **Account ID**.
2. **My Profile → API Tokens → Create Token** → шаблон «Edit Cloudflare Workers» → добавить строку
   **Account → D1 → Edit** → создать, скопировать токен.
3. Развернуть (Node.js 20+), токен бота спросит сам:
```bash
cd bot/worker && npm ci
CLOUDFLARE_ACCOUNT_ID=… CLOUDFLARE_API_TOKEN=… bash deploy.sh
```
`deploy.sh` создаёт базу D1 (и вписывает её id в `wrangler.toml` — закоммитить), таблицы, разворачивает воркер,
кладёт секреты в Cloudflare (`BOT_TOKEN`; `LICENSE_KEY` — ключ подписи лицензий, создаётся один раз и больше
не перезаписывается; `WEBHOOK_SECRET`), ставит webhook и меню команд, печатает адрес сервера ключей и
**открытый ключ лицензий** (вшить в приложение). Повторный запуск — обновление: данные и ключ подписи остаются.
Перед запуском остановить бота на Python с тем же токеном (webhook и polling вместе не работают).

| Что | Как |
|---|---|
| Цены, ссылка на APK, поддержка, режим оплаты | `[vars]` в `worker/wrangler.toml` → `bash deploy.sh` (или в панели Cloudflare → воркер → Settings → Variables) |
| Журнал воркера вживую | `npx wrangler tail` |
| Данные | `npx wrangler d1 execute DB --remote --command "SELECT …"`; копия — `npx wrangler d1 export DB --remote --output oda.sql` |
| Перенос ключа подписи с Python | `LICENSE_KEY=$(base64 -w0 data/license_ed25519.key \| tr '+/' '-_' \| tr -d '=') bash deploy.sh` |

**Проверка без Cloudflare и Telegram — имитация** (`npm test` в `worker/`): воркер запускается локально
(`wrangler dev`, своя D1), вместо Telegram — поддельный Bot API. Пользователи «Алиса», «Боб», «Мэллори»
нажимают кнопки и шлют команды, «телефоны» вводят ключи. 27 сценариев: меню и цвета кнопок, тарифы (1–5
устройств), выдача ключа, пробный день один раз (и при трёх одновременных нажатиях), активация и подпись
лицензии (подделка не проходит), лимит устройств (и при одновременном вводе), проверка раз в сутки, профиль,
продление, смена устройства, истёкший и отключённый ключ, защита от подбора (429), все разделы справки, чужие
ключи, сломанные обновления, секрет webhook. `npm run parity` — сверка всех экранов и лицензий с ботом на Python.
Оба запускаются в CI.

## Развёртывание на VPS (вариант с Python)
Нужен сервер с Ubuntu 22.04/24.04 или Debian 12, 1 vCPU и 1 ГБ памяти хватает с запасом. **Где:** за пределами
РФ (Финляндия, Нидерланды, Германия): бот обращается к api.telegram.org, а адреса Telegram в РФ режутся
(журналы ODA: 149.154.160.0/20). Сервер ключей при этом должен открываться из РФ без VPN — обычный зарубежный
адрес по HTTPS открывается; если начнут резать, домен можно пустить через Cloudflare. **Домен** (A-запись на IP
сервера) нужен для HTTPS — приложение будет ходить на `https://<домен>/v1/…`.

На сервере, под root, одна команда — спросит токен, ваш Telegram ID, домен и контакт поддержки:
```bash
sudo bash -c "$(curl -fsSL https://raw.githubusercontent.com/Wddis/Pol/ccr-016bf782-9cd9fj/bot/deploy/install.sh)"
```
Что делает `deploy/install.sh`: ставит Docker, скачивает код в `/opt/oda`, пишет `deploy/.env` (права 600),
открывает порты (если включён ufw), запускает `docker compose` (бот и сервер ключей, с доменом — ещё Caddy
с сертификатом Let's Encrypt), ставит ежедневную резервную копию (04:17, хранится 14 дней). Контейнеры —
`restart: always`: бот сам поднимается после сбоя и перезагрузки сервера.

| Команда (в `/opt/oda/bot/deploy`) | Что делает |
|---|---|
| `docker compose logs -f bot` | Журнал бота |
| `./update.sh` | Обновить до последней версии ветки и перезапустить (данные и `.env` остаются) |
| `./backup.sh` | Резервная копия базы и ключа подписи в `data/backups` (копируйте и вне сервера) |
| `nano .env` → `./update.sh` | Цены, ссылка на APK, контакт поддержки, режим оплаты |

Проверено в Docker: образ собирается, сервер ключей отвечает, копия создаётся, политика перезапуска `always`,
вариант с Caddy собирается.

## Запуск без Docker
Секреты — только в окружении, не в коде и не в чате.

```bash
cd bot
python3 -m venv .venv && .venv/bin/pip install -r requirements-dev.txt
.venv/bin/python -m pytest -q                 # тесты без Telegram
BOT_TOKEN=… .venv/bin/python -m oda_bot        # бот + сервер ключей на :8080
```
Без `BOT_TOKEN` работает только сервер ключей. В журнале при запуске — открытый ключ лицензий
(«вшить в приложение»).

Docker: `docker build -t oda-bot bot && docker run -d --restart=always -e BOT_TOKEN=… -p 8080:8080 -v oda-data:/app/data oda-bot`.

| Переменная | По умолчанию | Что это |
|---|---|---|
| `BOT_TOKEN` | — | Токен от BotFather |
| `ODA_DATA_DIR` | `data` | База `oda.db` и закрытый ключ `license_ed25519.key` (**беречь и копировать**: без него старые лицензии не проверить, нужен новый APK) |
| `ODA_API_HOST`, `ODA_API_PORT` | `0.0.0.0`, `8080` | Адрес сервера ключей |
| `ODA_PRICE_WEEK`, `ODA_PRICE_MONTH`, `ODA_PRICE_3M` | `0` | Цены, ₽ (0 — в боте «[ЦЕНА]») |
| `ODA_EXTRA_DEVICE_PCT` | `50` | Наценка за каждое устройство сверх первого, % |
| `ODA_FREE_MODE` | `1` | 1 — ключи без оплаты (пока оплаты нет) |
| `ODA_APK_URL` | — | Ссылка «Скачать ODA» |
| `ODA_SUPPORT` | — | Контакт поддержки (например, @username) |
| `ODA_ADMIN_IDS` | — | id владельцев в Telegram через запятую: настройка иконок (`/icons`) |
| `ODA_TG_PROXY` (или `HTTPS_PROXY`) | — | HTTP-прокси до Telegram, если сервер ходит в интернет через него (нужен `pip install aiohttp-socks`) |

Меню команд бот выставляет сам при запуске; те же команды для BotFather (`/setcommands`), если нужно вручную:
```
start - Главное меню
buy - Купить ключ
trial - Пробный день
profile - Мой профиль
help - О приложении и поддержка
```

| `oda_bot/__main__.py` | Запуск: сервер ключей и бот (long polling) в одном процессе |
| `oda_bot/config.py` | Настройки из окружения |
| `oda_bot/keys.py` | Формат ключа, ввод ключа как угодно (`normalize`), тарифы, цена с устройствами |
| `oda_bot/db.py` | SQLite: пользователи, ключи, устройства; активация, проверка, продление, смена устройства |
| `oda_bot/license.py` | Подпись лицензий Ed25519 и проверка (как в приложении) |
| `oda_bot/api.py` | HTTP-сервер ключей для приложения, защита от перебора |
| `oda_bot/icons.py` | Иконки кнопок (custom emoji): имена, сохранение, выключение при отказе Telegram |
| `assets/oda-avatar.png`, `.svg` | Аватарка бота = иконка приложения ODA |
| `deploy/` | VPS: `docker-compose.yml` (бот + Caddy для HTTPS), `install.sh`, `update.sh`, `backup.sh`, `.env.example` |
| `oda_bot/views.py` | Экраны бота: текст + кнопки (без сети, проверяются тестами) |
| `oda_bot/handlers.py` | Команды и кнопки; кнопки меняют сообщение на месте |
| `tests/` | Ключи, база, лицензии, HTTP-сервер, все экраны |
