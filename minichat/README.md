# MiniChat — минималистичный клиент сообщений VK

Самостоятельное Android-приложение (package `app.minichat`), не связанное с Kate Mobile.
Подключается к аккаунту VK как клиент и работает с личными сообщениями: список диалогов,
переписка, отправка, входящие в реальном времени. APK ~21 КБ, одно разрешение —
`INTERNET`.

## Почему это решает проблему «Flood control»

С 7 сентября 2026 VK считает вызовы API отдельно для каждого приложения (`client_id`).
У Kate Mobile все пользователи ходят под одним общим `client_id`, его месячная квота
исчерпана, поэтому сервер отвечает ошибкой 9 «Flood control». MiniChat не содержит
встроенного `client_id`: при входе вы указываете ID **своего** Standalone-приложения VK,
и все запросы (включая `messages.send`) считаются по квоте вашего приложения.

Клиент также бережёт квоту: новые сообщения приходят через User Long Poll (долгие
GET-запросы к серверу Long Poll — они не тратят вызовы API), запросы ограничены по
частоте, а в списке диалогов показан счётчик вызовов API за текущий месяц.

## Как пользоваться

1. Создайте Standalone-приложение на https://vk.com/apps?act=manage, включите Implicit
   Flow и укажите Redirect URI `https://oauth.vk.ru/blank.html`.
2. Установите APK, введите числовой **ID приложения** и войдите в свой аккаунт VK.
3. Откроется список диалогов. Нажмите на диалог, читайте и отправляйте сообщения.

Токен хранится только в приватном хранилище приложения и отправляется исключительно на
`api.vk.ru` и сервер Long Poll VK. Встроенных чужих учётных данных в приложении нет.

## Возможности

- Вход через собственное приложение VK (OAuth Implicit Flow в WebView).
- Список диалогов с именами собеседников, названиями бесед и счётчиком непрочитанного.
- История переписки, отправка сообщений, пометка прочитанным.
- Входящие сообщения в реальном времени (User Long Poll v3).
- Обработка капчи (код 14): показывается картинка, после ввода запрос повторяется.
- Ошибки сервера показываются как есть, с кодом и текстом. Неудачная отправка помечается
  «⚠ не отправлено» — исчезновение ошибки никогда не выдаётся за успешную отправку.
- Ошибка авторизации (код 5) возвращает на экран входа. Ошибка 9 не считается
  авторизационной и не разлогинивает.

## Структура

| Файл | Назначение |
|---|---|
| `Api.java` | HTTP-слой: один POST на вызов, троттлинг, разбор ошибок VK |
| `Vk.java` | методы `messages.*` и разбор ответов |
| `LongPoll.java` | User Long Poll v3 в фоновом потоке |
| `Store.java` | сессия, ID приложения, счётчик вызовов за месяц |
| `Bg.java` | выполнение работы вне main-потока |
| `LoginActivity` / `DialogsActivity` / `ChatActivity` | экраны |

## Сборка

```
export ANDROID_HOME=/path/to/android-sdk            # platform 34, build-tools 34.0.0
export MINICHAT_KEYSTORE=/path/to/minichat.jks       # для подписанного release
export MINICHAT_KS_PASS=...                           # пароль и ключа, и хранилища, alias minichat
gradle :app:assembleRelease
```

Без `MINICHAT_KEYSTORE` собирается обычный `assembleDebug`. APK: `app/build/outputs/apk/`.

## Тесты

`gradle :app:testDebugUnitTest` — 13 тестов на Robolectric («симуляция телефона»):
реальные экраны прогоняются против локального мок-сервера VK.

- вход: нечисловой ID отклоняется; токен сохраняется из OAuth-редиректа; посторонние URL
  игнорируются; ошибка OAuth показывается и ничего не сохраняет;
- диалоги: без токена — переход на вход; список с именами и беседами; ошибка 5 —
  разлогин; ошибка 9 показывается и **не** разлогинивает;
- чат: история от старых к новым; отправка уходит именно пользовательским токеном;
  ошибка отправки помечает сообщение «не отправлено» (без фиктивного успеха);
  капча → повтор → успех; входящее через Long Poll появляется в чате.

## Проверка на реальном устройстве

Автотесты идут против мок-сервера, живой аккаунт VK не использовался. На устройстве:
войдите под своим приложением, отправьте сообщение себе («Избранное») и убедитесь, что
оно появилось на vk.com. Если VK вернёт «no right to use messages» (код 15), вашему
приложению нужно выдать доступ к сообщениям на стороне VK.
