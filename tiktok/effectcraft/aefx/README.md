# aefx — перенос эффектов After Effects в EffectCraft без урезаний

Система конвертации `.ffx` / `.aep` → EffectCraft.

```bash
cd tiktok/effectcraft
python3 aefx_cli.py inspect  preset.ffx                      # что лежит в файле
python3 aefx_cli.py convert  preset.ffx out/ [--strict]      # команды для runner.js + отчёт + IR
python3 aefx_cli.py verify   out/preset.steps.json run/aefx_state.json   # сверка с тем, что реально на сайте
python3 -m unittest aefx.tests.test_aefx                     # 20 тестов, без сети
python3 aefx/tests/site_check.py                             # применить на живом сайте и сверить всё
```

`aeconv/ffx2ec.py` и `aeconv/aep2ec.py` переносят эффекты через aefx. Готовые ЦК: `../cc/apply_cc.py`.

## 1. Правило

Ничего не пропускается молча. Каждый параметр исходного эффекта получает строку в отчёте; всё, что не перенесено,
помечено как потеря с причиной. Результат проверяется на сайте: дошло ли каждое значение, ключ и выражение.

## 2. Как устроено

Три слоя, у каждого одно правило.

**Слой 1 — `ir.py`: прочитать всё.** Файл разбирается в промежуточное представление (IR). На каждый параметр:
определение из самого файла (тип, имя, группа, умолчание, диапазон, пункты списка), все компоненты значения,
каждый ключ целиком (время, интерполяция входа/выхода, roving, continuous/auto bezier, скорость и влияние по
каждому измерению, касательные), выражение, arb-данные, ссылки на слой/маску. На эффект — имя, вкл/выкл,
Compositing Options. Что не разобралось, остаётся сырыми байтами с пометкой `unparsed`.

**Слой 2 — `convert.py`: перенести и отчитаться.**
- Эффект ищется во всём каталоге сайта (`catalog/ec_catalog.json`: 306 эффектов, 3017 параметров, снят с живого
  EffectCraft скриптом `catalog/harvest.js`): по match name Adobe, по таблице соответствий, по имени.
- Параметры сопоставляются по имени + группе + типу. Переносятся все, включая равные умолчанию.
- Ключи — со всем, что перечислено выше. Списки — по подписи пункта. Цвет ARGB 0–255 → RGBA 0–1.
  Точки — в долях слоя и пересчитываются **на сайте** по фактическому размеру слоя (`runner.js`, `$frac`).
- Arb-данные — декодерами (`decoders.py`; сейчас Hue/Saturation).
- **Сторонние плагины** (`thirdparty.py`). Запустить сам плагин на сайте нельзя (см. §4). Поэтому каждый параметр
  плагина ставится на слой контролом «Эффект › Параметр» (Slider / Color / Point / Angle / Checkbox Control)
  со значением, всеми ключами и выражением 1:1, а встроенные эффекты-эмуляции получают **формулы-выражения**
  от этих контролов. Ничего не запекается: анимация остаётся живой и редактируемой на сайте.
- Учёт (`ledger.py`): каждый параметр получает ровно одну строку. Необработанный параметр автоматически
  становится потерей. Тест проверяет это на всех файлах.

| Статус | Класс | Смысл |
|---|---|---|
| `EXACT` `CONVERTED` `DECODED` `CALIBRATED` | без потерь | перенесён (как есть / с пересчётом единиц / из arb / по формуле калибровки) |
| `DEFAULT` `INERT` | без потерь | нет аналога, но значение = умолчанию плагина / параметр на картинку не влияет |
| `DERIVED` | эмуляция | параметр стороннего плагина участвует в формуле эмуляции |
| `STORED` | **потеря** | сохранён на слое контролом, но эмуляция его не использует |
| `CLAMPED` | **потеря** | значение вне диапазона EffectCraft |
| `LOSS` | **потеря** | не перенесён (причина — в строке) |

`--strict` возвращает код 2, если есть хоть одна потеря.

**Слой 3 — `verify.py`: проверить на сайте.** С `"aefxVerify": true` в конфиге `driver.js` раннер после применения
сохраняет проект и возвращает его состояние. `verify` сверяет с файлом AE каждое значение, имя эффекта,
каждый ключ (время, значение, интерполяция, ease, касательные, roving) и каждое выражение, а также ловит
ошибки выражений и незамеченные обрезания.

## 4. Чего система сделать не может — и говорит об этом прямо

1. **Сторонние плагины не становятся побитовой копией.** Веб-сборка EffectCraft 0.9.2 плагины не грузит:
   `effect.plugins.load` → «WebAssembly effect plug-ins are not available in this build». Код Sapphire / BCC /
   Deep Glow закрыт. Рецепты — это сборки из встроенных эффектов; коэффициенты в формулах подобраны на глаз,
   с рендером настоящего AE не сверялись (AE нет). В отчёте такие эффекты всегда помечены «эмуляция».
2. **Magic Bullet Looks.** Look — цепочка инструментов в недокументированном блоке `MBL2`. Переносятся Exposure
   и Hue/Saturation; остальные (Colorista, Haze, Mojo, 2-Strip, Diffusion…) идут в отчёт как `LOSS` со значениями.
3. **Effect Opacity и маски эффекта** (Compositing Options): в EffectCraft 0.9.2 их нет → `LOSS`.
4. **Arb-данные без декодера** (в первую очередь Curves): формат блока неизвестен, образца файла нет → `LOSS`,
   байты сохранены в IR. Декодер добавляется одной функцией в `decoders.py`.
5. **Ссылки на слои** в `.ffx` не хранятся; в `.aep` нужна карта слоёв (`layer_map`), иначе `LOSS`.

Что не проверено на настоящих файлах (в репозитории их нет):
- форматы ключей, кроме 1D (2D/3D, пространственные, цветовые), реализованы по публичному описанию AEP и
  проверены на синтетических файлах `tests/make_ffx.py`, а не на файлах из AE;
- путь `.aep` (`aep2ec.py` → aefx) проверен тестом на синтетическом узле слоя, настоящий `.aep` не прогонялся;
- рецепты S_Shake, S_Emboss, S_WarpChroma, S_ScanLines, BCC Lens Blur / Rays / Halftone, Deep Glow, Godrays
  проверены на синтетических параметрах (имена параметров — по документации плагинов).

При первом же настоящем файле: `inspect` → `convert --strict` → `site_check.py файл` покажут, всё ли сошлось.

## 5. Как расширять

- **Рецепт плагина** — функция в `thirdparty.py`:
  ```python
  @recipe("S_Glow")
  def s_glow(c, e):
      g = Target(c, "Glow")
      g.expr("radius", "{Glow Width} * {Width X} * thisComp.height / 1080 * 0.5")   # {Имя параметра AE}
  ```
  Контролы создаются сами. Чего формулы не коснулись, уйдёт в отчёт как `STORED`.
- **Декодер arb** — `@special("Имя эффекта EffectCraft")` в `decoders.py`.
- **Новая версия EffectCraft** — `node catalog/harvest.js raw.json && python3 catalog/build_catalog.py raw.json`.
- **Калибровка** (EffectCraft рендерит параметр иначе) — `CALIB_AFFINE` / `CALIB_EXPR` в `convert.py`.

## Файлы

| Файл | Назначение |
|---|---|
| `ir.py` | чтение `.ffx` / `.aep` без потерь → IR |
| `convert.py` | IR → команды EffectCraft, учёт, ожидания для проверки |
| `decoders.py` | декодеры arb-данных стандартных эффектов |
| `thirdparty.py` | рецепты сторонних плагинов (контролы + формулы) |

| `catalog/` | каталог эффектов EffectCraft и скрипты его снятия |
| `tests/` | `test_aefx.py` (юнит-тесты), `make_ffx.py` (сборка тестовых `.ffx`), `site_check.py` (проверка на сайте) |
| `../runner.js` | дополнен: `$frac`, фиксация обрезаний, `aefxVerify` |
